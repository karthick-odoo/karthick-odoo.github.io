Featured project: Hostel / PG Room Allocation

Odoo 19 custom module, client project, 2026.

Python · XML · QWeb · OWL · SCSS · PostgreSQL

  • Designed and developed an end-to-end hostel and PG management module with 8 custom models covering hostels, rooms, beds, tenants, bed allocations, rent billing and reporting.
  • Integrated with Odoo Accounting: automated pro-rata monthly rent invoices, payment status synced back to allocations, and a customised invoice PDF with a PAID / UNPAID stamp.
  • Automated rent reminders with the invoice PDF attached, allocation confirmations and payment receipts using 3 scheduled actions and mail templates.
  • Implemented role-based security with 3 user groups (Viewer, Manager, Administrator) and record rules limiting each manager to assigned hostels.
  • Built an interactive OWL dashboard (occupancy, rent collected, outstanding and overdue amounts) and a visual rooms-and-beds map with booking and maintenance actions.
  • Developed 6 management reports with charts, exportable to PDF and Excel, plus graph and pivot views.
  • Enforced business rules (gender-based allocation, one active allocation per tenant or bed, closure only after full payment) and wrote the user guide and a 53-case test document.

How I solve business problems

Two common Odoo scenarios, shown the way I would approach them. These are illustrative examples, not client results.

Large orders were confirmed without a manager’s approval

Problem → approach → result

Problem. Any salesperson could confirm any quotation, including very large or heavily discounted ones.

QuotationOver limit?Manager approvalOrder confirmed

Approach. Add an approval limit, block confirmation above it with a clear message, notify the manager and keep an audit trail, using a small override that keeps upgrades easy.

Standard Odoo (simplified)

# sale.order
def action_confirm(self):
    ...  # confirms any order,
    ...  # whatever the amount

My version

def action_confirm(self):
    for order in self:
        if order.amount_total > order.company_id.approval_limit:            raise UserError(_("Manager approval is required."))    return super().action_confirm()

Simplified for illustration. approval_limit is a custom field added on the company.

Result. Orders above the limit stop for review, smaller orders flow as before, and the change stays small.

Stock counts were manual, and shelves ran empty

Problem → approach → result

Problem. Stock lived in spreadsheets, counts were done on paper and buyers reacted only after items sold out.

Scan itemStock updatedReorder rulePurchase order

Approach. Configure Inventory with barcode scanning, set reorder rules per product, and connect them to purchase orders for approval, then train the warehouse team and document the process.

Result. Less manual counting and earlier warning before stock-outs.
